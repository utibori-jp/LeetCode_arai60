# 929 - Unique Email Addresses

- URL: https://leetcode.com/problems/unique-email-addresses/description/
- カテゴリ: Hash Table / String
- 難易度: Easy

## 解いた日

## 問題の本質
メールアドレスを「正規化」したとき、何種類残るかを数える問題。
`@` の前後で処理が異なる点と、`+` 以降を無視するルールに気づけるかがポイント。

## 自分のアプローチ
いったん正規化してSetに追加。最後にSetの要素数を返せば終わりでは？


## レビュー結果
全テストケースパス。正規表現を使って正規化する方針は正しく、コードも明快。

### 計算量
- 時間: O(N × M) — N はメール数、M は1メールの最大文字数
- 空間: O(N × M) — `email_set` に正規化済みアドレスを格納

### より良い解法
正規表現なしで `str` メソッドだけでも同等の処理が書ける。

```python
normalized_email_set = set()
for email in emails:
    local, domain = email.split('@')
    local = local.split('+')[0].replace('.', '')
    normalized_email_set.add(f"{local}@{domain}")
return len(normalized_email_set)
```

`split('+')[0]` で `+` 以降を除去、`replace('.', '')` でドットを除去。
計算量は同じだが、`re` モジュール不要でシンプル。

### 類題・関連パターン
- 文字列正規化 + Set による重複除去パターン
- LeetCode 771 Jewels and Stones（文字集合との照合）
- LeetCode 1002 Find Common Characters（文字操作）

## 学んだこと

この問題のポイントは、以下の2つで回答でどちらも網羅できていた。
- 先にメールアドレスを正規化して比較しやすくする
- Setを使うことでユニークな集合を作る
ただ一方で、俺の解法だと20msほどかかったのに対して、提示されたより良い解法はほぼ0msでテストケースをパスした。
この違いは、正規表現エンジンのオーバーヘッドにより発生した。re.sub()は内部で、パターンをステートマシンにコンパイル→汎用の正規表現エンジンを起動→マッチ位置を探しながら文字列を再構築という処理を行っている。一方で、splitやreplaceは、Pythonの組み込みメソッドでc言語で実装された単純な線形スキャン。この差が数字として出た。
「正規表現は強力だが、単純な文字列操作では組み込みメソッドの方が早い」というのが今回の追加の学びだった。
